# 电子束直写 · 剂量图综合台

纯前端（TypeScript + React + Vite）的矩形孔径剂量图综合工具。**全部计算在浏览器本地完成，无后端、无任何网络请求。**

## 工艺背景

电子束直写设备只能使用**已标定的矩形孔径**逐次击发，每次击发给其覆盖矩形内的每格**恰加 1 单位剂量**，同一孔径可重复击发。
贪心策略优先选择大孔径，常因覆盖到零剂量格而“封死”后续区域。本工具因此采用**完整穷举**：枚举所有可行的孔径放置多重集，保证全局最优。

## 优化准则（与工艺约定严格一致）

1. **最小化击发次数**；
2. 击发次数相同时，将每次击发的零基元组 `(top, left, height, width)` 按字典序排序后，对**整份列表**再取字典序最小；
3. 输出三态结论：
   - **唯一最优**：返回唯一方案；
   - **并列最优**：展示字典序最前的**两份规范方案**，可切换逐步查看；
   - **不可实现**：在不允许过曝的前提下无解。

方案保证精确命中目标（每格累计剂量恰为目标值，**不过曝、不欠曝**），重复击发允许。

### 输入约束

| 项目 | 约束 |
| --- | --- |
| 剂量图 | 2~5 行、2~6 列；每格整数 0~4；总剂量 ≤ 36 |
| 允许孔径 | 1~8 种；高、宽均为正整数；不得超出网格（必然越界的尺寸直接拒绝） |
| 击发矩形 | 零基 `top/left`，`height/width` 为正整数，覆盖范围不得越界 |

任何输入改动都会**立即撤下旧结论**，需重新点击“启动综合”。

### 导入格式

- 纯文本剂量图：每行 2~6 个整数（空格/逗号/中文逗号等分隔），2~5 行：

  ```
  0 1 0
  1 1 1
  0 1 0
  ```

- JSON（两字段均可缺省）：

  ```json
  { "grid": [[0, 1, 0], [1, 1, 1], [0, 1, 0]],
    "apertures": [[1, 2], [2, 1], [1, 1]] }
  ```

## Docker 交付

静态站点由 nginx 提供，多阶段构建（deps → build → web/verify）。

### 启动站点（宿主机端口可配置）

```bash
# 默认映射到宿主机 8080
docker compose up --build -d

# 自定义宿主机端口
HOST_PORT=9000 docker compose up --build -d
# 或复制 .env.example 为 .env 后修改 HOST_PORT
```

健康检查：容器每 5 秒 `wget --spider http://127.0.0.1:80/`，compose 据
`service_healthy` 条件编排依赖。

### verify：一次性核验服务

服务名 **`verify`**，顺序执行：① 代码测试（vitest）② 构建检查（tsc + vite
build）③ 对运行中的站点做 HTTP 冒烟（首页、带哈希 JS 产物、健康端点、SPA
回退）。**跑完自行退出，并以退出码报告结果（0 成功 / 非 0 失败）**。

```bash
# 一条命令：构建、等待 web 健康、执行核验、以 verify 的退出码作为 compose 退出码
docker compose --profile verify up --build \
  --abort-on-container-exit --exit-code-from verify verify

# 等价写法（run 形式）
docker compose --profile verify run --build --rm verify
```

## 求解器正确性说明（src/solver.ts）

- 每种允许孔径在网格上的每个不越界放置构成一个“模板”，按
  `(top,left,height,width)` 全序编号；方案 = 模板上的非负计数向量（多重集）。
- 计数 DFS 对模板编号单调推进、每模板枚举使用次数 0..cap，**每个多重集恰好
  枚举一次**；cap 同时由“覆盖格最小剩余剂量（防过曝）”和“剩余面积”界定。
- 剪枝只排除可证明严格劣于当前最优的子树（后缀覆盖并集、面积发数下界），
  不损害完整性；120 组随机用例与独立朴素枚举器逐解对拍一致。
- 总剂量 ≤ 36、单发面积 ≥ 1，故搜索空间有限；5×6/8 孔径/总剂量 36 的
  最坏规模实测约百毫秒级。
